## 三、第一课 · AI 纪要

> 2026 年首届智能体软件工程黑客松启动宣讲会，面向参赛选手讲解赛事规则、技术路线、实操指引与平台使用规范。

### 1. 赛事背景与发起支撑

- **发起与支持方**：上海交大凌云团队牵头，联合上海交大、新加坡国立大学；华为云提供 Docker 云基础设施，中国电信提供下游算力，Tree、Mediamax 提供 IDE/Token 赞助，启悟、DataFlow 社区提供问题支撑。
- **行业变革背景**：软件工程随编程语言抽象层级提升演进，大模型时代将出现「需求编译」全新阶段；上海交大已完成内部课程试点，本科生可从复杂需求端到端生成 12306、携程类可运行网站。
- **赛事核心价值**：推动软件工程进入类似算法竞赛的「LeetCode 时刻」——输入需求即可输出可通过全量测试的可靠软件。

### 2. 赛事规则与评分体系

- **参赛核心任务**：选手不写业务代码，核心是构建可自动完成需求处理的软件工程智能体；需求采用结构化 DSL（领域特定语言）描述，树状组织，含 ID、多模态描述、子需求依赖、场景步骤与预期结果。
- **三维评分标准**：
  - **测试通过率**：智能体生成的软件通过官方未公开验证测试的比例（选手自测用例不纳入评分）。
  - **构建成本**：按各模型官方人民币计价标准核算总消耗。
  - **迭代可维护性**：需求变更时智能体增量更新的效率与成本。
- **赛事阶段与分区**：
  - 初赛：0→1 生成完整可运行软件，考核通过率 + 构建成本。
  - 决赛：在初赛版本基础上新增需求迭代效率考核。
  - 新手区（Junior）vs 高手区（Senior）：通过率 ≥80% 自动进入高手区，高手区比拼成本性价比。
- **配套规则**：方案需开源；选手数据相互隔离；评分无人工干预。

### 3. 官方参考技术路线：ARK 测试驱动法

- **核心设计**：测试左移——完成需求拆解与架构设计后，优先生成测试用例，再引导大模型生成代码，通过测试反馈迭代直至全部通过。本质是多源交叉信号（测试反馈 + 编译器报错）约束大模型概率发散。
- **分层实现流程**：需求拆解为 UI/API/功能/数据模块 → 逐层生成单元测试、集成测试、端到端 GUI 测试 → 每完成一个需求节点自动 Git 提交 → 支持随时回退历史版本定位错误节点。
- **路线优化建议**：测试用例完备性、断言精度仍有优化空间；通过约束 harness 可实现低成本弱模型达到高成本强模型的效果；官方仅提供 ARK 参考，不限定单/多智能体方案。

### 4. 配套支持与实操安排

- **竞赛平台**：arc-bench.com，含 Playground 演示区、比赛提交区、研究资料区；个人空间获取专属 API Key，meter.arc-bench.com/user 查 Token 消耗。
- **系列 Lab**：Lab1 孔桂宇走通需求编译全流程；Lab2/Lab3 吕明曦讲 TDD 实操与成本对比；Lab4 张晨阳演示 VS Code 插件端到端流程；平台提交演示由张文杰、张希文讲解。
- **后续支持**：课件汇总至 GitHub 仓库；启悟社区设课程/赛事讨论区；后续将邀请开源社区高手分享其他技术路线。

## 四、第二课 · AI 纪要

> 智能体开发赛事实操授课，围绕赛事资源、工具使用、赛题规则、备选技术路线展开。

### 1. 赛事合作与资源说明

- **赛事合作方**：华云提供云计算底座，雅信、数联提供奖金与 Token 赞助，中国电信、魔搭社区提供 Token 基建；字节跳动提供智能编程辅助。
- **魔搭社区权益**：20 万+开源模型库，参赛选手额外获 500 魔力值；Notebook 提供免费 CPU + 注册用户 GPU 免费额度，内置千问 qwen code 工具；创空间支持一键部署作品。
- **模型使用规则**：练习阶段不限平台模型；正式比赛需用赛事指定 API，商业模型费用选手自担。

### 2. GUI 层面测试驱动开发实操

- **演示场景**：网页注册表单，先由大模型生成初始网页，再用 Playwright 生成测试用例驱动多轮迭代修复。
- **环境配置**：Node 24.x、npm 11.x，克隆 lab 仓库装依赖，`pms run setup process` 安装 chromium；可选用魔搭社区 GLM-5.3-Flash、千问 3.8 FlashMax。
- **效果**：弱算力模型多轮迭代后整体 Token 消耗仅 0.05 元；经 TDD 引导后验证集通过率显著提升。

### 3. 智能体版本管理与增量编译

- **Lab05 版本回溯**：左侧栏展示全流程节点，view diff 查看代码修改，move current branch here 切换历史节点重跑。
- **Lab06 增量需求编译**：在已有需求旁新增同级节点，填写描述/依赖/场景后运行，系统自动跳过已有功能；新增完整功能约 5 元成本。
- **Lab07 细粒度测试增量**：局部修复时在对应节点下新增测试用例，仅针对该功能点迭代；单功能修复约 0.3 元。

### 4. Arcbench 赛题与提交流程

- **赛题**：12306、携程、图书管理、便签、社区、购物网站共 6 个真实 Web 应用，体量/评分与初赛一致。
- **提交流程**：下载模板 → 实现代码 → 上传提交；增量赛道自动以普通赛道最高分应用为初始基础。
- **结果查看**：排行榜查看通过率、Token 消耗、模型成本。

### 5. Octus 备选技术路线

- **核心特性**：Rust 编写的嵌入式智能体内核，模块化可扩展，类 Claude Code 的端到端代码生成能力。
- **对接方式**：通过官方 ark 适配包将 Octus 代码对接至 Arkbench 平台。
- **流程**：本地部署跑通 → 打包 zip → 上传评测。

## 五、第三课 · AI 纪要

> 智能体打榜大赛官方技术培训，围绕参赛智能体开发、实操流程、架构逻辑及规则答疑展开。

### 1. Octopus 适配打榜方案与实操指引

- **精简适配版设计**：全功能主线持续维护，适配版默认关闭非代码类技能、多线程模块、沙箱，仅保留核心会话与代码工具链，减少 Token 消耗。单仓库即可完成全流程开发打包。
- **本地开发与提交**：克隆 Octopus-Ark 仓库 → 装依赖、配置密钥 → 本地运行验收脚本 → 修改 release 下载地址 → 打包提交。迭代遵循「修改代码→本地编译验证→打包上传」小步循环。
- **打榜规则**：含 Smoke、Arkbenchweb、RPHY 等赛道，核心评分维度为通过率 + Token 消耗效率；支持查看历史提交、任务流向图、运行日志。

### 2. Ark 智能体架构与核心特性

- **系统定位**：专注端到端需求编译的特化智能体，固定主工作流 + 节点智能体的集中编排模式。
- **核心运行逻辑**：设计、测试生成、实现三个专属智能体通过共享代码库通信，按需求节点队列依次完成各阶段任务。
- **差异化特性**：
  - **可追溯性体系**：需求、接口、测试节点显式建模关联，支持出错后反向追溯。
  - **全流程版本记录**：每节点完成后自动 Git commit。
  - **增量编译**：决赛阶段核心功能，支持在已有代码基础上迭代新需求。
- **二次开发边界**：只需保证 main.py 输入输出、requirements 依赖规范，其余模块可自由修改。所有提交包内置 agent runtime SDK。

### 3. 参赛规则答疑

- **模板更新**：以 competition 页面版本为准，向下兼容。
- **运行环境限制**：初赛禁止智能体主动联网搜索/调用外部接口；提交包经二次人工+大模型审查，禁止预置答案。
- **决赛规则**：自动读取初赛最优应用作为输入，无需手动上传初始代码。

### 4. 智能体框架选型建议

| 框架 | 优势 | 适用场景 |
|---|---|---|
| **Octopus** | 调度自由、可对接廉价国产模型、规避审核、架构易扩展 | 有架构调整需求的选手 |
| **Ark** | 适配性最优，内置需求拆解+TDD+流水线完整脚手架 | 快速上手参赛 |
| **Codex** | 能力成熟但偏人工交互，源码复杂门槛高 | 与全自动端到端任务适配性弱 |
